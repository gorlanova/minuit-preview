# Why Minuit

Minuit has been designed to adapt to a wide range of use cases, according to the following principles:

## Minimal configuration

The main goal is to provide ready-to-use components with as little required configuration as possible. 95% of the time, you do not need to set up all the internal elements of a component, only the data to display. That way, you can keep your code clean and concise, and let Minuit handle the rest.

## Numerous options

When you do need more advanced features, Minuit provides a wide range of options to customize the look and behavior of the components: display variations, complex data structures, extra logic, etc. You can choose the level of complexity that suits your needs, without being overwhelmed by unnecessary options.

## Low specificity styles

Components are styled with low specificity CSS, allowing you to implement your own styles without using `!important` or complex selectors. Minuit also provides a global design system that you can customize to change the look of all components at once.

## Built-in accessibility

Accessibility is a core principle of Minuit. All components are designed to be accessible by default, following best practices and WCAG criteria. On the rare occasions where you will need to do some extra work to make sure a component is fully accessible, Minuit provides clear guidelines and tools to help you achieve that.
